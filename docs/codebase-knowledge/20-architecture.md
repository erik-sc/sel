# Architecture (implemented)

## Layers and dependency direction

```
renderer (sandboxed React + zustand)      src/renderer/src
        |  window.api only
preload (contextBridge, adds clientId)    src/preload/index.ts
        |  ipcRenderer.invoke / on
main (validation, SQLite, files, git, CLIs, network)   src/main
        both sides import types and pure helpers from  src/shared
```

- The renderer is an ordinary sandboxed web page with context isolation and no node integration (src/main/index.ts:108-110).
- The renderer cannot open connections: the CSP sets `connect-src 'none'` (src/renderer/index.html:19), and the session cancels every request that `isAllowedRequest` rejects (src/main/index.ts:230-232, src/main/security.ts:114).
- Every invoke handler is wrapped: trusted sender, client id, wait for first-run seeding, run, then drain changes (src/main/ipc.ts:70-92); the wrapper is applied to each channel of `INVOKE` and to nothing else (src/main/ipc.ts:295).
- Inside main, features follow three tiers: pure modules, an Electron-free service, and a `*Bridge` that wires Electron (src/main/ai/locate.ts:5-6, src/main/herman/service.ts:21-23, src/main/sync/engine.ts:55-68).
- Inside the renderer the intended direction is ui, then store, then editor and shell, then features; store imports only the toast, boot and shared (src/renderer/src/store/tabs.ts:2, src/renderer/src/store/blocks.ts:5).
- Heavy code is loaded lazily on both sides: `await import` in main (src/main/ipc.ts:129, src/main/ipc.ts:192) and `React.lazy` wrappers with `preload*` functions in the renderer (src/renderer/src/editor/lazy.tsx:7-22).

## Data stores and external services

- **SQLite**, one file `sel.db` under `userData` (src/main/legacy.ts:5, src/main/index.ts:308). Tables `blocks`, `settings`, `blocks_fts`, `page_versions`, `sync_state` (src/main/db/schema.ts:9, src/main/db/schema.ts:25, src/main/db/schema.ts:30, src/main/db/schema.ts:50, src/main/db/schema.ts:66), `page_links` (0.7.0) and `activity` (0.8.0, src/main/db/schema.ts:116). WAL mode and other pragmas are set in `configure` (src/main/db/schema.ts:95-107).
- **Migrations** are an append-only array where index plus one is `user_version` (src/main/db/schema.ts:4-7, src/main/db/schema.ts:109-131).
- **Activity log** (0.8.0 D1): the `activity` table holds light events (screen/page opened, page edited per minute, task created/completed/postponed with its project, pomodoro start/finish, AI request with its origin), ids and times only. `Repository.activity` (src/main/db/repository.ts:151, src/main/db/activity.ts:41) buffers them in memory and writes in one transaction from a one-minute timer, a full buffer or `close()` (src/main/db/repository.ts:183). Edits and task changes come from the repository's own transactions after commit (src/main/db/repository.ts:293, src/main/db/repository.ts:724, src/main/db/activity.ts:219), so sync's `applySync` never records any; screens and pages come from the renderer over `activity:open` (src/renderer/src/activity/tracker.ts). Setting `activity.enabled` (default on, not synced) is re-read by `setSetting`, so turning it off drops the buffer at once. Sync reads neither the table nor the setting, and no prompt includes it; local backups (a copy of the file) do. The Fluxos screen (src/renderer/src/flows) reads it through `activity:summary` only, and the weekly word about the rhythm (src/main/activity/rhythm.ts) reads its rows in main, on this computer, when `activity.rhythm` is on (default off); `activity.rhythmSaid` remembers the week.
- **Tree storage**: a child holds `parent_id` (src/main/db/repository.ts:690), and the parent's `content` array holds the order (src/main/db/repository.ts:389-390); root order is a setting (src/main/db/repository.ts:48-50).
- **Full-text search** is FTS5 maintained by hand in the repository, not by triggers (src/main/db/repository.ts:370-376, src/main/db/repository.ts:645-648).
- **Files under `userData`**: images (src/main/files.ts:33), recordings (src/main/meetings/index.ts:20), the whisper engine (src/main/meetings/index.ts:57), the encrypted calendar list and event cache (src/main/briefing/index.ts:15-19), the sync clone and sealed keys (src/main/sync/index.ts:111, src/main/sync/index.ts:119), the AI sandbox directory (src/main/ai/index.ts:78).
- **Settings rows that hold lists**: the balloon keeps its last conversations in `ai.conversations` and the log of what the AI applied (with the inverse ops of each batch) in `ai.applied`, trimmed under the 1 MB setting cap by the renderer and cleaned again by main; never synced (src/shared/aiHistory.ts, src/shared/ai.ts:217-220). Chosen over a table so that no migration is needed. The persona's memory is a list in `ai.memory` too (at most 50 short facts), written by main alone (src/shared/aiMemory.ts, src/main/ai/memory.ts).
- **Secrets** go through Electron `safeStorage`: calendar URLs (src/main/briefing/index.ts:40-45) and derived sync keys, never the passphrase (src/main/sync/index.ts:36-56).
- **External programs**, all spawned without a shell and with a rebuilt environment: the Claude Code CLI (src/main/ai/service.ts:253-264, src/main/ai/command.ts:180; also `claude mcp list` and a start stopped at its init event, from Settings → AI → Claude's tools, `AiService.runCli`), system git (src/main/sync/git.ts:370-378, src/main/sync/git.ts:186), whisper.cpp (src/main/meetings/whisper/run.ts:179, src/main/meetings/whisper/run.ts:148).
- **Network the app itself opens**: calendar fetches (src/main/briefing/net.ts:376) and whisper downloads from pinned URLs with SHA-256 checks (src/main/meetings/whisper/download.ts:215, src/main/meetings/whisper/download.ts:252-257), and the opt-in update check against GitHub Releases through electron-updater, off by default and loaded only when a check runs (src/main/updates/schedule.ts:46, src/main/updates/register.ts:33). The renderer additionally loads https images (src/main/security.ts:110-120).
- **No telemetry or crash reporter**: a grep over `src` and root configs for sentry, crashReporter, telemetry and analytics matched only an environment flag for the child CLI (src/main/ai/command.ts:189). Updates are opt-in (above); packaging writes the update feed files but uploads nothing (electron-builder.yml:33, package.json `dist`).

## Boundaries and seams

- **An invoke call is declared once.** Its signature is a promise-returning method of `Api` (src/shared/api.ts:27); its channel is a `namespace:method` line in `INVOKE`, checked against `Api` in both directions (src/shared/api.ts:279-394). The rule is that `api.a.b.c` answers on `a:b.c` (src/shared/ipc.ts:1-10). The preload builds one method per line and nothing else (src/preload/index.ts:30, src/shared/ipc.ts:52); main's handler maps are typed per namespace, so a missing or undeclared handler fails typecheck (src/main/invoke.ts:16, src/main/ipc.ts:280-295). Events and fire-and-forget sends stay constants written out by hand (src/shared/api.ts:262-268, src/preload/index.ts:43-110). Tests pin both sides: src/preload/index.test.ts, src/main/ipc.test.ts.
- **All block writes funnel through ops.** `Repository.apply` runs them in one transaction (src/main/db/repository.ts:829-853); the client mirrors the same semantics for optimistic updates (src/renderer/src/store/ops.ts:20-31). AI proposals and database edits use this same path (src/renderer/src/ai/applyActions.ts:23, src/renderer/src/database/actions.ts:20-23).
- **Change fan-out**: mutations mark ids, the wrapper drains them after the handler, and `ChangeFeed` sends one event per origin per turn to every window, the originator included (src/main/ipc.ts:82-87, src/main/changes.ts:49-52, src/main/ipc.ts:58-61). Non-window origins are `sync` and `meetings` (src/main/ipc.ts:209, src/main/ipc.ts:238).
- **Feature registration seam**: briefing, meetings, herman, feedback and updates return their namespace's handler map (`Handlers<'briefing'>` and so on) beside their hooks, and `registerIpc` puts every map behind the one wrapper (src/main/briefing/register.ts:32, src/main/ipc.ts:244-295). Only the meetings audio frames go to `ipcMain.on` directly (src/main/meetings/register.ts:121-122).
- **Test seams**: an in-memory repository on `node:sqlite` (src/main/db/testing.ts:12-22), injectable clocks (src/main/db/repository.ts:100-103), fake CLIs (src/main/ai/fixtures/fake-claude.mjs:6-8, src/main/meetings/whisper/fixtures/fake-whisper.mjs:1), and a sync harness with bare local remotes that needs a real git (src/main/sync/harness.ts:18-24).
- **Development seams** are environment variables honoured only in unpackaged builds, for example `SEL_AI_CLI` (src/main/ai/index.ts:54-56, src/main/ai/index.ts:76) and the dev renderer URL (src/main/security.ts:17-29).

## Where implemented differs from documented

- README says the app "makes no network requests of its own" apart from four named cases (README.md:41); the code agrees, but the comment calling the calendar module "the one place where sel itself goes on the network" (src/main/briefing/net.ts:9) is stale since the whisper downloader exists (src/main/meetings/whisper/download.ts:215).
- README lists `shared/` as "types both sides agree on" (README.md:76); it also holds runtime validators and parsers such as `splitActions` (src/shared/actions.ts:182) and `checkRemoteUrl` (src/shared/sync.ts:155).
- README's layering implies main never depends on the renderer (README.md:73-76); in fact Markdown export imports the renderer's pure database logic (src/main/markdown.ts:20-23), made possible by the node tsconfig (tsconfig.node.json:15).
- README says all style values live in one tokens file (README.md:78); compliance was not verified this session (unverified).
- The schema comment lists four version kinds (src/main/db/schema.ts:54) but sync stores a fifth, `sync` (src/main/db/repository.ts:1472).
- README shows Windows only under "Get it" (README.md:47) while the code carries macOS and Linux branches (src/main/index.ts:102-103, src/main/index.ts:120); only a Windows target is packaged (electron-builder.yml:47-50).
