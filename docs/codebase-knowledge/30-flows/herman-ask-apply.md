# Flow: ask Herman, get a proposal, press Apply

Trigger: a click on the persona in its corner (`open` in src/renderer/src/herman/Dock.tsx:380), or Ctrl+J, the shortcut of the `toggle-assistant` command (`AI_COMMANDS` in src/shared/ai.ts, collected into `APP_SHORTCUTS` by src/shared/shortcuts.ts) matched in `before-input-event` (src/main/menu.ts). On macOS the menu accelerator is the path. The command palette (Ctrl+K) and the sparkle button of the top bar run the same command (src/renderer/src/commands/builtin.ts, src/renderer/src/shell/TopBar.tsx). Since 0.8.0 there is no side panel: the conversation is a balloon that comes out of the persona.

## Open the balloon

2. `BalloonHost`, a `content` overlay of the AI feature (order 15, just above the persona's corner), lazy-loads `Balloon` while the gate is enabled and open — src/renderer/src/ai/feature.ts:17, src/renderer/src/ai/Host.tsx:18. The balloon is one component whether the persona is on or off; it reads `useHerman.on` for the name and the copy — src/renderer/src/ai/Balloon.tsx:288
3. Where it goes: the Dock publishes the persona's corner and size into the always-loaded gate (`setBalloonAnchor`, src/renderer/src/herman/Dock.tsx:262, src/renderer/src/ai/balloonGate.ts:85); `usePlacement` (src/renderer/src/ai/Balloon.tsx:241) feeds that, the area's size, the balloon's height and the page's caret (`caretBox`, src/renderer/src/herman/avoid.ts:13, the same the Dock uses) into the pure `placeBalloon` — src/renderer/src/ai/placement.ts:43. Beside the figure with a tail toward it; above it when the area is narrow; at the other edge (or faded) when the caret is under it. While it is open the Dock adds `is-talking` and holds its own speech bubble — src/renderer/src/herman/Dock.tsx:439
4. Before anything is typed the balloon shows up to four suggestions chosen without AI from the moment (`useMoment` reads overdue tasks from `briefing.get` and whether the open page is a transcribed meeting) — `suggestionsFor`, src/renderer/src/ai/suggest.ts:91. A suggestion is sent as a question (`suggest`, src/renderer/src/ai/Balloon.tsx:394); the meeting one runs the page's own "Write up notes" (`requestPageAi(pageId, 'consolidate')`) instead
5. Focus: the field takes the keyboard once the balloon is placed, Tab stays inside, Esc stops a running answer, then leaves "Earlier" or the log, then closes (`onKeyDown`, src/renderer/src/ai/Balloon.tsx:441); on close the focus and the selection go back to where they were (`useFocusReturn`, src/renderer/src/ai/Balloon.tsx:215)

## The persona's memory (0.8.0 A3)

Automatic, decided by Érik: nothing is asked before a fact is kept. Stored in `ai.memory` (written by main only; `[{ id, text, at, source, uses }]`, at most 50 facts of 200 characters; never synced), switched by `ai.memoryEnabled` (on unless false). Pure rules in src/shared/aiMemory.ts.

1. `startMemory` (called by the AI feature's `init`) listens with `onReplyDone`; each finished answer goes to main with the pages it was about: the request's `pageId` and the tab route the question was asked from (`route`, kept in memory on the user message, because a question on a private page goes without its `pageId`) — src/renderer/src/ai/memoryNotes.ts:54, src/renderer/src/ai/conversations.ts:321
2. `ai:remember` → `AiBridge.remember` → `PersonaMemory.remember`: refuses with the memory off; reads a turn (`conversationId:messageId`) once; gives nothing for a conversation about a page private from the AI (`privacyChecker` on every page id); runs only when `worthRemembering` (the user speaks of themselves: "I", "my", "eu", "prefiro"…, or wrote at length, and a real answer came) — src/main/ai/register.ts:37, src/main/ai/memory.ts:122, src/shared/aiMemory.ts:205
3. The extraction is a request of its own through the same service: `runPrompt` with `{ model: 'haiku', origin: 'memory' }` (`RunTarget.model` overrides `ai.model`), no tools, the prompt from `buildMemoryPrompt` (KNOWN facts and the CONVERSATION fenced as data, strict JSON `{"facts":[…]}` asked). It is logged in the activity log as `{ kind: 'ai', area: 'memory' }`, which is what a usage count by origin (C5) can read — src/main/ai/index.ts:113, src/main/ai/memory.ts:63
4. `parseMemoryReply` reads only the strict JSON (a code fence tolerated), at most 3 facts, each ≤ 200 characters; `findSecret` drops anything that looks like a password, key, token, document, account or card number, or a long run of digits; `addFacts` skips what is already kept (`sameFact`) and, past 50, lets the least used and then the oldest go — src/shared/aiMemory.ts:219, src/shared/aiMemory.ts:138, src/shared/aiMemory.ts:265
5. What was kept comes back to the window, and `rememberReply` adds "Remembered: …" / "Lembrei: …" with "Undo" under that answer (`addReplyNote`); Undo is `ai:memory { op: 'remove' }` — src/renderer/src/ai/memoryNotes.ts:18

Settings → AI → Memory (`MemorySettings`, src/renderer/src/ai/MemorySettings.tsx): the switch, every fact editable in place (Enter or leaving the field; an empty one is deleted; a secret is refused), delete one, delete all (`ai:memory` ops `edit`, `remove`, `clear`, applied by `PersonaMemory.apply`). Off: nothing new is read or kept, nothing kept is sent, at once. Tests: src/shared/aiMemory.test.ts (secret filter, parsing, guard, caps), src/main/ai/memory.test.ts (once per turn, private exclusion, off switch, the MEMORY section, the request with the small model against the fake CLI), src/renderer/src/ai/Memory.test.tsx.

## The persona's introduction (0.8.0 A1)

A sheet in five steps said by the persona beside its figure (`Onboarding`, src/renderer/src/ai/Onboarding.tsx, mounted by `OnboardingHost` as a window overlay of order 72): (1) Claude Code found or not (`refreshAiStatus`, install command, choose the program) and the model (`ai.model`: default, opus, sonnet, haiku); (2) Herman or Hermine and the outfit, stored with `saveHermanSetting` (src/renderer/src/herman/wardrobe.tsx), the figure changing at once; (3) questions (who, work, projects of Tasks — not the private ones — and other projects, answer length, language, tone) that `composeContext` turns into a draft shown in a textarea, editable; "Save and continue" writes `mergeContext(existing, draft)` to `ai.context` (after what was there, never over it; refused past 8,000 characters) — src/renderer/src/ai/onboardingDraft.ts; (4) pages to pin: the pinned ones, then those `activity.summary().returning` says you come back to, then `pages.listRecent`, never one private from the AI (`aiPrivacyNow` after `loadAncestors`), pinned with `toggleContextPage`; (5) the user's MCP servers, turned on as Read only (`ai.mcpServers`). Every step has "Skip this step"; the close button is "Skip the introduction". No AI call is made.

When: by itself once, the first time the balloon is opened or AI is turned on in Settings (`maybeOnboard`), when `ai.onboarded` is not true; a profile that already has kept conversations is marked onboarded quietly at start (`loadOnboarded`). Closing it, finished or skipped, sets `ai.onboarded` (`closeOnboarding`), and opened from the balloon, opens the balloon. Again: Settings → AI → "Redo the introduction" and the palette command `ai-onboarding` ("Redo the introduction", keywords "refazer apresentação") — src/renderer/src/ai/gate.ts:82-122, src/shared/ai.ts (`AI_ONBOARDING_COMMANDS`), src/renderer/src/ai/feature.ts. Copy in en and pt-BR, in Herman's words through `personifyCopy` (src/renderer/src/ai/onboardingCopy.ts); the line naming the other persona is taken raw. Tests: src/renderer/src/ai/Onboarding.test.tsx (happy-dom, axe), src/renderer/src/ai/onboardingDraft.test.ts.

## Private from AI (0.8.0, A5)

A page, a database or a project of Tasks can be kept from the AI. The rule is one pure function, `isPrivateForAi` / `privacyChecker` (the same answer remembered for one read) and `aiPrivacy` (with the reason) — src/shared/aiPrivate.ts:85-106. It is stored on the blocks, so it syncs and exports with them: `props.aiPrivate: true` on a page or database (everything under it inherits: sub-pages, blocks, rows; a linked view of a private database is private too), and `props.aiPrivateProjects` (option ids of `tasks.project`) on the Tasks database for the rows of a private project — src/shared/types.ts. Neither enters a page's history: `rootProps` leaves them out and a restore keeps the current marks — src/main/db/versions.ts, src/main/db/repository.ts.

Where it is enforced, all in the main process (the window's lock is only a display):

- The request: `withoutPrivatePage` drops the page, its blocks and the selection from a question asked on a private page and remembers it (`privateAsks`), so WORKSPACE says only "one the user keeps private"; any other action on a private page (summarize, title, improve, the notes of a meeting…) is refused with `AI_PRIVATE_PAGE_MESSAGE` before anything runs — src/main/ai/index.ts:217, src/main/ai/request.ts:142. `loadContext` refuses one too (the floor) — src/main/ai/request.ts:161.
- The Markdown the AI reads: `pageToMarkdown` / `blocksToMarkdown` take `hidden` and leave out a private sub-page or database (title and all) and the rows of a private project, also inside charts and calculations — src/main/markdown.ts:254, src/main/markdown.ts:337. An export passes nothing and is whole.
- WORKSPACE and RELATED: the outline, "Inside it", the databases, "Edited lately" and the FTS-related pages skip private ids — src/main/ai/context.ts:157, src/main/ai/context.ts:196.
- The day: `promptData` leaves out private tasks; it feeds the question about the day, "Brief me" and the alarms' briefing — src/main/briefing/service.ts:532.
- Project and database context (A4): `contextScopes` gives nothing for a private page, a private database (or a linked view of one) or a project in `aiPrivateProjects`; `loadScopes` reads each pinned page through the same checker, so a pinned page made private later is left out — src/shared/aiScope.ts:119, src/main/ai/standing.ts:61. The editor refuses to pin a private page (`canPinToScope`) and says when the project or database itself is private (its context is kept, never sent) — src/renderer/src/ai/scopeContext.ts, src/renderer/src/ai/ScopeContextDialog.tsx.
- Pinned pages: `loadStanding` skips a private one (pinned before it became private, or on another device) — src/main/ai/standing.ts:44. The window refuses to pin one (`toggleContextPage` returns `'private'`, after loading the pages above it) and the menu says why; Settings lists a pinned private page as "kept here, never sent" — src/renderer/src/ai/gate.ts:148, src/renderer/src/shell/pageMenu.tsx:101, src/renderer/src/ai/ClaudeSettings.tsx.
- The workspace tools (Claude's, read-only): search, outline, recent and audit skip it; read_page, read_database and outline with a private root answer `AI_PRIVATE_MESSAGE`; read_page of a parent leaves the private child out; read_database leaves private-project rows out; `toolActivity` never names it — src/main/ai/tools.ts:288, src/main/ai/tools.ts:310.
- sel for other apps (MCP): decided to follow the same rule. The endpoint runs the same `callTool` (reads hidden as above), and the writing tools refuse a private page, database or row as "private" (append, create inside, add or update a row) — src/main/external/service.ts, src/main/ai/writes.ts. The server's instructions say so — src/main/mcp.ts.

In the window: "Private from AI" / "Privado para a AI" in both page menus (checked and greyed out when the mark is on a page above, the project or the source database), a lock beside the title and on the sidebar row (`PrivateLock`), a "Project private from AI" toggle on a Tasks project and a lock in the list of projects — src/renderer/src/shell/pageMenu.tsx:117, src/renderer/src/ai/PrivateLock.tsx, src/renderer/src/ai/privacy.ts, src/renderer/src/tasks/TasksScreen.tsx. On a private page the conversation balloon says the page is private and that a general question still works, shows "Private page: not sent" instead of the page chip, drops the selection, offers no page suggestions (`suggestionsFor` with `page.private`) and sends the question without `pageId` — src/renderer/src/ai/Balloon.tsx, src/renderer/src/ai/suggest.ts. Summarize and Suggest title are not offered on it.

Not covered (open): a relation cell or an inline link in a public page shows a private row's or page's title as stored text; the count of rows of a public database includes private-project rows; calendar events are not blocks and are never private.

For what comes later (memory A3, project context A4, routines C): ask `privacyChecker` / `isPrivateForAi` about every id before reading it, and read pages through `pageToMarkdown(…, { hidden })`.

## The user's own MCP servers (Claude Code 2.1.296, checked on 2026-10-22)

- `--restricted` loads none of the user's settings files, so no server of `~/.claude.json` and no plugin server; it still loads the claude.ai connectors unless `--strict-mcp-config` (or `--safe-mode`, `--bare`, `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `disableClaudeAiConnectors`) turns them all off. Without an allow-list, connectors are all or nothing.
- `allowedMcpServers` in a `--settings` file is honoured: a connector matches only by `serverUrl` (its display name "claude.ai X" does not match), a `--mcp-config` server by `serverName`. Everything not listed is dropped, with "blocked by enterprise policy" on stderr.
- Tool names: `mcp__<name with non [A-Za-z0-9_-] as _>__<tool>`, so "claude.ai Veleiro" → `mcp__claude_ai_Veleiro__get_me`. `permissions.deny` in the settings file removes tools from the model's list (wildcards work); with `--permission-prompts none`, any tool not in `permissions.allow` or `--allowedTools` is denied when called.
- Connector addresses are in no local file: `claude mcp list` prints them (`AiBridge.scanServers`, src/main/ai/index.ts:402, parsed by `parseMcpList`, src/main/ai/claudeMcp.ts:128). Tools are read from the `system/init` event of a start that is stopped there (`serverTools`, src/main/ai/index.ts:413); a start always needs a prompt, so it may count as one small request.
